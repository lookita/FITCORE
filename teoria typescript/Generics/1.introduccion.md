# Generics — La Caja Mágica de TypeScript

---

## 🧠 Primero, entendamos el PROBLEMA

Imaginate que sos dueño de una panadería. Tenés tres tipos de cajas:

- Una caja **roja** solo para guardar medialunas 🥐
- Una caja **azul** solo para guardar tortas 🎂
- Una caja **verde** solo para guardar galletitas 🍪

¿No sería mejor tener **una sola caja mágica** que pueda guardar cualquier cosa, pero que recuerde qué tipo de comida pusiste adentro?

Eso exactamente son los **Generics** en TypeScript.

---

## 📦 ¿Qué es un Generic?

Un Generic es como decirle a TypeScript:

> "Oye, todavía no sé qué tipo de dato voy a usar aquí, pero cuando me lo digan, voy a recordarlo y usarlo siempre consistentemente."

El símbolo que usamos es `<T>`, donde la **T** significa **Tipo** (Type en inglés). Pero podría ser cualquier letra, es solo una convención.

---

## ❌ Sin Generics: El Problema Real

Mirá este código SIN usar Generics:

```typescript
// Tengo que hacer una función DIFERENTE para cada tipo
function mostrarNumero(valor: number): number {
  console.log(valor);
  return valor;
}

function mostrarTexto(valor: string): string {
  console.log(valor);
  return valor;
}

function mostrarBooleano(valor: boolean): boolean {
  console.log(valor);
  return valor;
}

// ¡Tres funciones que hacen EXACTAMENTE lo mismo!
// Si necesito cambiar algo, tengo que cambiarlo en las tres.
// Esto es un HORROR de mantener.
```

---

## ✅ Con Generics: La Solución Elegante

```typescript
// Una sola función que sirve para CUALQUIER tipo
function mostrar<T>(valor: T): T {
  console.log(valor);
  return valor;
}

// Ahora la misma función sirve para todo:
mostrar(42); // TypeScript sabe: T = number
mostrar("Lucas"); // TypeScript sabe: T = string
mostrar(true); // TypeScript sabe: T = boolean
mostrar([1, 2, 3]); // TypeScript sabe: T = number[]
```

¿Ves la magia? **Una sola función** que funciona para todos los tipos, y TypeScript sabe exactamente qué tipo estás usando en cada momento.

---

## 🔤 ¿Cómo se lee `<T>`?

Cuando ves `function mostrar<T>(valor: T): T`, se lee así:

1. `<T>` → "Voy a usar un tipo que todavía no conozco. Lo voy a llamar `T`."
2. `(valor: T)` → "El parámetro `valor` va a ser de ese tipo desconocido."
3. `: T` → "Y también voy a devolver algo del mismo tipo."

Es como un contrato: **"Lo que entra tiene que ser igual a lo que sale."**

---

## 🤔 ¿Por qué T y no X o Z?

Por convención, los programadores usan letras específicas:

- **`T`** → Type (el tipo principal)
- **`K`** → Key (cuando hablan de claves de un objeto)
- **`V`** → Value (cuando hablan de valores)
- **`E`** → Element (cuando hablan de elementos de una lista)

Podés usar cualquier nombre: `<MiTipo>`, `<Dato>`, `<X>`. Pero `T` es lo más común.

## 🏋️ Ejemplo Real en ObsidiantFit

### Guardar cualquier preferencia del usuario:

```typescript
// Sin Generic: necesito una función por cada tipo de preferencia
function guardarNombre(valor: string) {
  /* ... */
}
function guardarEdad(valor: number) {
  /* ... */
}
function guardarActivo(valor: boolean) {
  /* ... */
}

// Con Generic: UNA función para todo
function guardarPreferencia<T>(
  clave: string,
  valor: T,
): { clave: string; valor: T } {
  // Guardamos en la base de datos...
  return { clave, valor };
}

// La misma función sirve para TODO:
guardarPreferencia("nombre", "Lucas"); // T se convierte en string
guardarPreferencia("edad", 25); // T se convierte en number
guardarPreferencia("esEntrenador", true); // T se convierte en boolean
guardarPreferencia("rutinas", ["PPL", "EMOM"]); // T se convierte en string[]
```

## 🎒 Generics con Arrays

Uno de los usos más comunes: funciones que trabajan con listas de cosas.

```typescript
// Esta función devuelve el primer elemento de CUALQUIER lista
function primero<T>(lista: T[]): T {
  return lista[0];
}

const primerEjercicio = primero(["Dominadas", "Flexiones", "Plancha"]);
// TypeScript sabe que primerEjercicio es un string ✅

const primerPeso = primero([80, 75, 72]);
// TypeScript sabe que primerPeso es un number ✅
```

---

## 🔗 Generics con Múltiples Tipos

Podés usar más de un tipo genérico al mismo tiempo:

```typescript
// Una función que toma dos cosas diferentes y las combina
function combinar<T, U>(primero: T, segundo: U): { primero: T; segundo: U } {
  return { primero, segundo };
}

// Combinar un usuario con su rutina
const resultado = combinar(
  { nombre: "Lucas", nivel: 12 }, // T = objeto usuario
  ["Dominadas", "Flexiones"], // U = array de strings
);
```

---

## 🎯 Los 3 Superpoderes de los Generics

### Superpoder 1: Reutilización

Escribís el código **una vez** y funciona para cualquier tipo.

### Superpoder 2: Seguridad de Tipos

TypeScript sigue rastreando el tipo. Si entraste con `number`, no podés cometer el error de tratarlo como `string`.

```typescript
function duplicar<T>(valor: T): T {
  return valor;
}

const resultado = duplicar(42);
resultado.toUpperCase(); // ❌ Error: los números no tienen toUpperCase!
```

### Superpoder 3: Código Más Limpio

En lugar de tener 20 funciones casi idénticas, tenés 1 función genérica.

---

## 📚 ¿Dónde más aparecen los Generics?

Los Generics están en todos lados en TypeScript. Cuando hacés:

```typescript
const lista: Array<string> = ["a", "b", "c"];
// Array<string> es un Generic! Es como decir: "una lista DE strings"

const promesa: Promise<number> = new Promise((resolve) => resolve(42));
//resolve es una funcion que recibe un parametro, en este caso 42, que es un number. y resolve es una funcion que devuelve un promise, en este caso un promise de number.
// Promise<number> es un Generic! "Una promesa QUE devuelve un número"
```

---

## 🏗️ Generics en Objetos (Interfaces y Types)

No solo sirven en funciones. También se pueden usar en tipos e interfaces:

```typescript
// Una "caja" genérica que puede contener cualquier cosa
type Caja<T> = {
  contenido: T;
  etiqueta: string;
  fechaCreacion: Date;
};

// Una caja de números (rutinas por semana)
const cajaDeRutinas: Caja<number[]> = {
  contenido: [3, 4, 3, 5, 4],
  etiqueta: "Sesiones por semana",
  fechaCreacion: new Date(),
};

// Una caja de texto (logros del usuario)
const cajaDeLogros: Caja<string> = {
  contenido: "Primera dominada a una mano",
  etiqueta: "Logro desbloqueado",
  fechaCreacion: new Date(),
};
```

## 🚫 Limitaciones con Generics (Constraints)

A veces querés decirle al Generic que no puede ser CUALQUIER cosa, sino que tiene que tener ciertas propiedades. Usás `extends` para eso:

```typescript
// Solo acepta cosas que tengan una propiedad "nombre"
function saludar<T extends { nombre: string }>(objeto: T): string {
  return `Hola, ${objeto.nombre}!`;
}

saludar({ nombre: "Lucas", nivel: 12 }); // ✅ Tiene nombre
saludar({ id: 1 }); // ❌ Error: no tiene nombre!
saludar(42); // ❌ Error: un número no tiene nombre!
```

## 🔑 Lo que tenés que recordar

1. `<T>` es un **marcador de posición** para un tipo que todavía no sabemos.
2. **Lo que entra con tipo `T` tiene que salir con tipo `T`**.
3. TypeScript **deduce automáticamente** el tipo cuando llamás la función.
4. Podés usar **constraints** con `extends` para restringir qué tipos acepta.
5. Los Generics son la base de los **Utility Types**, **Promises**, **Arrays** y el **Repository Pattern** en tu backend.
