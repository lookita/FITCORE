# 4. `extends` vs `implements` — Ser o Parecer

---

## 🧠 La Gran Diferencia (ELI10)

En programación, a veces quieres decir que algo **ES UN** hijo de otro, y otras veces solo quieres decir que algo **ACTÚA COMO** otro.

---

## 🧬 Nivel 1: `extends` (Herencia: "Vínculo de Sangre") 👪

Cuando usas `extends`, heredas el código. No tienes que escribirlo de nuevo.

```typescript
class Motor {
  encender() { console.log("Brum brum... 🚗"); }
}

// El Auto ES UN vehículo con motor. Ya sabe encenderse.
class Auto extends Motor {}

const miAuto = new Auto();
miAuto.encender(); // ✅ Ya lo tiene en el ADN
```

---

## 📜 Nivel 2: `implements` (Contrato: "Vínculo de Papel") ✍️

Cuando usas `implements`, firmas un contrato. No heredas nada de código, solo heredas la **obligación** de tener ciertas cosas.

```typescript
interface Movil {
  mover(): void; // El contrato dice que TENÉS que tener esta función
}

class Bicicleta implements Movil {
  // ❌ Error si no escribo 'mover'
  mover() {
    console.log("Pedaleando fuerte... 🚲");
  }
}
```

---

## 🏗️ Nivel 3: ¿Cuándo usar cada uno? (Intermedio)

| Situación | ¿Qué usar? | ¿Por qué? |
|---|---|---|
| Quieres **reutilizar** código que ya existe | `extends` | Para no escribir lo mismo dos veces. |
| Quieres que muchas cosas **distintas** se comporten igual | `implements` | Para asegurar que todas tengan los mismos botones/funciones. |
| Una clase necesita tener **múltiples** formas | `implements` | Puedes cumplir muchos contratos, pero solo tener un padre. |

---

## 🚀 Nivel 4: Ejemplo Maestro en ObsidiantFit

Imagina que tenemos un sistema de **Suscripciones**.

```typescript
// 1. EL CONTRATO: Todo lo que sea un "Pagable" debe poder cobrar
interface Pagable {
  cobrar(monto: number): void;
}

// 2. LA CLASE PADRE: Algo genérico
class Usuario {
  constructor(public nombre: string) {}
}

// 3. COMBINACIÓN: Un usuario que además firma el contrato de pago
class UsuarioPremium extends Usuario implements Pagable {
  constructor(nombre: string) {
    super(nombre);
  }

  // Obligado por 'implements Pagable'
  cobrar(monto: number) {
    console.log(`Cobrando $${monto} a ${this.nombre} vía Tarjeta.`);
  }
}

// 4. OTRO QUE CUMPLE EL CONTRATO: No es un usuario, pero también cobra
class TiendaSuplementos implements Pagable {
  cobrar(monto: number) {
    console.log(`Cobrando $${monto} por venta de Proteína.`);
  }
}
```

---

## 🔑 Resumen para recordar:

- **`extends`**: Es como heredar la casa de tus padres. Ya está construida, solo entras a vivir. (Reutilizas).
- **`implements`**: Es como inscribirte en un curso. Te dan una lista de exámenes que **tienes que aprobar** tú mismo. (Estandarizas).

En ObsidiantFit usaremos:
- `extends` para tipos de ejercicios o usuarios (heredar datos).
- `implements` para Repositorios o Servicios (cumplir contratos de funciones).
