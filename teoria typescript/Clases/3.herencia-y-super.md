# 3. Herencia y `super` — El Árbol Genealógico

---

## 🧠 ¿Qué es la Herencia? (ELI10)

Imagina que tienes un **Deportista**. Todos los deportistas tienen un nombre y saben "Entrenar".
Ahora quieres crear un **Futbolista** y un **Nadador**. 

- El **Futbolista** ES UN deportista (necesita nombre y entrenar), pero además sabe "Patear".
- El **Nadador** ES UN deportista, pero además sabe "Bucear".

En lugar de escribir el código de "nombre" y "entrenar" tres veces, el Futbolista y el Nadador **HEREDAN** del Deportista.

---

## 🛠️ Nivel 1: El `extends` básico (Fácil)

Usamos `extends` para decir que una clase es hija de otra.

```typescript
class Deportista {
  entrenar() {
    console.log("Entrenando duro... 💪");
  }
}

// Futbolista hereda de Deportista
class Futbolista extends Deportista {
  patear() {
    console.log("¡GOL! ⚽");
  }
}

const messi = new Futbolista();
messi.entrenar(); // ✅ Sabe hacerlo porque es hijo de Deportista
messi.patear();   // ✅ Sabe hacerlo porque es Futbolista
```

---

## 🏗️ Nivel 2: La palabra mágica `super` (Intermedio)

¿Qué pasa si el padre tiene un constructor? El hijo **está obligado** a llamar al padre para avisarle que nació. 
Para eso usamos `super()`.

```typescript
class Usuario {
  constructor(public nombre: string) {
    console.log(`Bienvenido, ${this.nombre}`);
  }
}

class Admin extends Usuario {
  constructor(nombre: string, public nivelDePoder: number) {
    super(nombre); // 👈 ¡OBLIGATORIO! Llama al constructor de Usuario
    console.log(`Admin con poder ${this.nivelDePoder} creado.`);
  }
}

const lucas = new Admin("Lucas", 999);
// Imprime:
// Bienvenido, Lucas
// Admin con poder 999 creado.
```

## 🚀 Nivel 3: Cambiando lo que hace el padre (Complejo)

A veces el hijo quiere hacer lo mismo que el padre, pero a su manera. Esto se llama **Sobrescribir** (Override).

```typescript
class Ejercicio {
  hacer() {
    console.log("Haciendo el ejercicio básico...");
  }
}

class FlexionExplosiva extends Ejercicio {
  // Sobrescribimos el método 'hacer'
  hacer() {
    super.hacer(); // ✅ Opcional: Primero hacemos lo básico del padre
    console.log("¡Y ahora salto con aplauso! 👏⚡");
  }
}

const flex = new FlexionExplosiva();
flex.hacer();
// Imprime:
// Haciendo el ejercicio básico...
// ¡Y ahora salto con aplauso! 👏⚡
```

## 🏋️ Ejemplo Real en ObsidiantFit

Vamos a modelar diferentes tipos de rutinas.

```typescript
class Rutina {
  constructor(public nombre: string, public duracionMin: number) {}

  comenzar() {
    console.log(`Iniciando rutina: ${this.nombre} (${this.duracionMin} min)`);
  }
}

class RutinaCalistenia extends Rutina {
  constructor(nombre: string, duracion: number, public tieneBarra: boolean) {
    super(nombre, duracion);
  }

  // Sobrescribimos para dar un mensaje especial
  comenzar() {
    super.comenzar();
    if (this.tieneBarra) {
      console.log("¡No olvides los guantes para la barra! 🧤");
    }
  }
}

const rutinaDeLunes = new RutinaCalistenia("Espalda Explosiva", 45, true);
rutinaDeLunes.comenzar();
```

---

## 🔑 Reglas de Oro de la Herencia:

1.  **Un solo padre**: Una clase solo puede heredar de **UNA** clase (no puedes tener dos `extends`).
2.  **`super()` primero**: Si el hijo tiene un constructor, lo primero que debe hacer es llamar a `super()`.
3.  **Heredas todo**: El hijo recibe todas las propiedades y métodos `public` y `protected` del padre. Los `private` no se heredan.
