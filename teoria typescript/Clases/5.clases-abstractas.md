# 5. Clases Abstractas — El Plano Maestro de ObsidiantFit 🏋️‍♂️

---

## 🧠 ¿Qué es una Clase Abstracta? (Nivel ELI5)

Imagina que en **ObsidiantFit** queremos registrar "Entrenamientos". Pero piénsalo bien: nadie hace un "Entrenamiento" a secas. Tú haces **Yoga**, haces **Crossfit** o haces **Powerlifting**.

La **Clase Abstracta** es como una idea que flota en el aire. Es un plano que dice: *"Para ser un entrenamiento en esta app, necesitas un nombre y una duración, pero yo no sé cómo se calculan tus calorías todavía"*.

- **REGLA DE ORO:** No puedes crear (usar `new`) una clase abstracta. Es un molde, no el pastel.

---

## 🛡️ Nivel 1: La Base Inquebrantable (Seguridad)

Usamos `abstract` para evitar que alguien (o nosotros mismos por error) cree objetos "genéricos" que no tienen sentido en el negocio.

```typescript
abstract class Entrenamiento {
  constructor(
    public nombre: string, 
    protected duracionMinutos: number
  ) {}

  // Un método NORMAL (con código): Todos los entrenamientos lo heredan igual
  iniciar() {
    console.log(`🚀 Iniciando ${this.nombre}... ¡A darle con todo!`);
  }
}

// ❌ ERROR: "Cannot create an instance of an abstract class."
// const rutinaX = new Entrenamiento("Algo", 30); 

class Yoga extends Entrenamiento {
  estirar() {
    console.log("🧘 Namasté... Estirando músculos.");
  }
}

const miClase = new Yoga("Yoga Flow", 60);
miClase.iniciar(); // ✅ Funciona porque lo heredó del padre
```

## 🏗️ Nivel 2: El Contrato de Obligación (Métodos Abstractos)

Aquí es donde **ObsidiantFit** se asegura de que todos los programadores sigan las reglas. El padre dice: *"Hijo, te obligo a tener esta función, pero tú decides cómo se hace"*.

```typescript
abstract class Ejercicio {
  constructor(public nombre: string) {}

  // ❗ MÉTODO ABSTRACTO: No tiene cuerpo { }, termina en ;
  // Obliga a que cada ejercicio calcule sus calorías de forma única.
  abstract calcularCalorias(): number;
}

class Flexiones extends Ejercicio {
  calcularCalorias() {
    return 5 * 10; // 5 kcal por cada 10 flexiones (ejemplo)
  }
}

class Correr extends Ejercicio {
  constructor(nombre: string, private km: number) {
    super(nombre);
  }

  calcularCalorias() {
    return this.km * 100; // 100 kcal por km
  }
}
```

## 🧙 Nivel 3: Arquitectura y Polimorfismo (Experto)

### 💎 Propiedades y Getters Abstractos
No solo los métodos pueden ser abstractos. También podemos obligar a definir valores.

```typescript
abstract class BaseRoutine {
  // Obligamos a que cada rutina defina su nivel de dificultad
  abstract readonly dificultad: 'Bajo' | 'Medio' | 'Alto';

  // Un getter abstracto
  abstract get intensidad(): number;

  public imprimirResumen() {
    console.log(`Rutina: ${this.dificultad} | Intensidad: ${this.intensidad}/10`);
  }
}

class RutinaPro extends BaseRoutine {
  readonly dificultad = 'Alto';
  
  get intensidad() {
    return 9.5;
  }
}
```

## 🏋️ Ejemplos Reales en ObsidiantFit

### 1. Sistema de Pagos (Multi-Pasarela)
Nuestra app puede cobrar por Stripe o PayPal. La base es la misma, pero el proceso de pago cambia.

```typescript
abstract class PasarelaPago {
  constructor(protected apiKey: string) {}

  // Lógica común: Validar que el monto sea positivo
  protected validarMonto(monto: number): boolean {
    return monto > 0;
  }

  abstract procesarPago(monto: number): Promise<boolean>;
}

class StripeGateway extends PasarelaPago {
  async procesarPago(monto: number) {
    if (!this.validarMonto(monto)) return false;
    console.log(`💳 Cobrando $${monto} vía API de Stripe...`);
    return true;
  }
}
```

### 2. Generador de Dietas (Planificación)
Dependiendo del objetivo (Bajar peso o Ganar músculo), la base es "Comer", pero el cálculo es abstracto.

```typescript
abstract class PlanNutricional {
  constructor(public usuario: string) {}

  abstract calcularMacros(): { proteinas: number, carbs: number, grasas: number };

  generarInforme() {
    const macros = this.calcularMacros();
    console.log(`Informe para ${this.usuario}: P:${macros.proteinas} C:${macros.carbs} G:${macros.grasas}`);
  }
}

class PlanVolumen extends PlanNutricional {
  calcularMacros() {
    return { proteinas: 180, carbs: 400, grasas: 80 }; // Superávit
  }
}
```

### 3. Sistema de Notificaciones
```typescript
abstract class Notificador {
  abstract enviar(mensaje: string): void;
}

class NotificadorEmail extends Notificador {
  enviar(msg: string) { console.log(`📧 Email: ${msg}`); }
}

class NotificadorWhatsApp extends Notificador {
  enviar(msg: string) { console.log(`🟢 WhatsApp: ${msg}`); }
```

## ⚔️ Clase Abstracta vs Interface

| Característica | Interface | Clase Abstracta |
|---|---|---|
| **¿Qué es?** | Un contrato de "forma" (puro TS). | Un "plano" parcial (JS real). |
| **Código real** | ❌ Prohibido. Solo firmas. | ✅ Permitido. Lógica compartida. |
| **Estado** | ❌ No tiene variables con valores. | ✅ Puede tener variables y constructor. |
| **Herencia** | Se usa `implements`. | Se usa `extends`. |

---

## 🔑 Resumen Maestro

1.  **Instanciación:** `abstract` = Prohibido hacer `new`.
2.  **Ahorro de código:** Todo lo común va en la clase abstracta.
3.  **Contrato estricto:** Los métodos abstractos obligan al hijo a programarlos.
4.  **Polimorfismo:** Puedes tratar a un `Yoga` o `Crossfit` simplemente como un `Entrenamiento`.
